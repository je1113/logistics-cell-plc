# 신호 명세서 (Signal Specification)

물류 분류 셀에서 PLC, 로봇, HMI가 주고받는 신호의 의미, 순서, 예외 처리를 정의한다.

> 주소는 Python 가상 PLC 서버와 클라이언트 사이에서만 쓰는 **학습용 가상 주소**다.
> 실제 LS PLC와 연동할 때는 XG5000 통신 설정과 매뉴얼에 맞춰 P/M 영역을 다시 매핑해야 한다.

## 1. 통신 구성

| 항목 | 값 |
|---|---|
| 프로토콜 | Modbus TCP |
| 서버 | 가상 PLC (`plc_sim/plc_server.py`), 127.0.0.1:5020 |
| 클라이언트 | 로봇 (`robot_sim/robot_client.py`), HMI (`hmi/CellHmi`), 측정 (`measure/measure.py`) |
| 데이터 영역 | Coil (1비트, 읽기·쓰기) |
| PLC 스캔 주기 | 50 ms |
| 클라이언트 확인 주기 | 로봇 50 ms · HMI 200 ms · 측정 10 ms |

## 2. 신호 목록

| Coil | 신호 | 방향 | 켜는 쪽 | 끄는 쪽 | 의미 |
|---|---|---|---|---|---|
| 0 | 피킹 요청 | PLC → 로봇 | PLC | PLC | 박스가 피킹 위치에 도착해 작업을 요청함 |
| 1 | 셀 정상 | PLC → 로봇·HMI | PLC | PLC | 알람이 없고 작업 요청이 가능한 상태 (안전 신호 아님) |
| 2 | 요청 수락 | 로봇 → PLC | 로봇 | 로봇 | 피킹 요청을 받았음 |
| 3 | 동작 중 | 로봇 → PLC | 로봇 | 로봇 | 피킹 작업을 수행 중 |
| 4 | 피킹 완료 | 로봇 → PLC | 로봇 | 로봇 | 피킹 작업을 마쳤음 |
| 5 | 박스 도착 | HMI → PLC | HMI | **PLC** | 박스 도착 요청 (PLC가 읽은 뒤 끔) |
| 6 | 알람 리셋 | HMI → PLC | HMI | **PLC** | 알람 해제 요청 (PLC가 읽은 뒤 끔) |
| 7 | 알람 | PLC → HMI | PLC | PLC | 타임아웃이 발생해 셀이 멈춘 상태 |

## 3. 정상 핸드셰이크

```
 HMI          PLC                          로봇
  │─ 박스 도착 ─>│                              │
  │             │─ 피킹 요청 ON ─────────────>│
  │             │<──────────── 요청 수락 ON ───│
  │             │<──────────── 동작 중 ON ─────│
  │             │<──────────── 동작 중 OFF ────│
  │             │<──────────── 피킹 완료 ON ───│
  │             │─ 피킹 요청 OFF ────────────>│
  │             │<──── 수락·완료 OFF (초기화) ──│
  │             │  다음 사이클 허용              │
```

| 단계 | PLC 상태 | 다음으로 넘어가는 조건 |
|---|---|---|
| 1 | IDLE | 박스 도착 → 피킹 요청 ON |
| 2 | WAIT_ACK | 요청 수락 ON |
| 3 | WAIT_DONE | 피킹 완료 ON → 피킹 요청 OFF |
| 4 | WAIT_CLEAR | 요청 수락 · 동작 중 · 피킹 완료 모두 OFF |
| 5 | IDLE | 다음 박스 대기 |

**원칙: 신호를 켠 쪽이 끈다. 단, HMI 버튼 신호는 PLC가 처리한 뒤 끈다.**
요청 해제와 응답 초기화까지 확인해야 이전 사이클의 완료 신호가 다음 사이클을 잘못 시작하지 않는다.

## 4. 예외 처리

| 상황 | 감지 조건 | PLC 동작 | 복귀 |
|---|---|---|---|
| 요청 수락 타임아웃 | 피킹 요청 후 3.0 s 안에 수락 없음 | 피킹 요청 OFF · 셀 정상 OFF · 알람 ON | 알람 리셋 |
| 작업 완료 타임아웃 | 수락 후 10.0 s 안에 완료 없음 | 피킹 요청 OFF · 셀 정상 OFF · 알람 ON | 알람 리셋 |
| 알람 중 박스 도착 | 알람 상태에서 박스 도착 | 무시 (로그만 남김) | 알람 리셋 후 다시 요청 |
| HMI 통신 끊김 | HMI 읽기 실패 | (PLC 동작 없음) HMI가 램프를 모두 끄고 "통신 끊김" 표시 | HMI에서 다시 연결 |
| 로봇 통신 끊김 | 로봇 읽기 실패 | (PLC 동작 없음) 로봇 클라이언트가 스스로 정지 | 로봇 재시작 |

## 5. 래더 로직과의 관계 (XG5000)

| 래더 (XG-SIM) | 의미 | 대응하는 가상 PLC 동작 |
|---|---|---|
| P0002 → TON T000 | 박스 감지 후 정지 위치까지 지연 | 박스 도착 → 피킹 요청 |
| T000 → P0041 | 피킹 요청 출력 | Coil 0 피킹 요청 |
| P0003 | 피킹 완료 입력 | Coil 4 피킹 완료 |
| P0004 b접점 | 로봇 동작 중 인터록 | Coil 3 동작 중 |
| M0000 | 비상 상태 유지 (리셋 전까지) | 알람 상태 유지 (Coil 7) |

래더와 가상 PLC는 직접 연결되어 있지 않다. 래더로 검증한 제어 흐름을 Python으로 같은 순서로 구현해 통신을 검증했다.

## 6. 아직 정의하지 않은 것

- **PLC 측 통신 끊김 감지:** 로봇이 주기적으로 바꾸는 하트비트 신호를 두고, 일정 시간 변화가 없으면 정지하는 방식으로 추가할 예정
- **비상정지:** 안전 회로(안전 릴레이, Safety PLC)에서 처리해야 하므로 이 명세의 범위에 넣지 않았다
